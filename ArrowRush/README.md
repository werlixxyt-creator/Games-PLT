# Arrow Rush

Онлайн-игра: зажимай нужную стрелку, заполняй ползунки один за другим быстрее соперников.
Сервер — ASP.NET Core 10 + SignalR (WebSocket), клиент — обычная страница (HTML/CSS/JS).

## Правила

- Ползунки стоят вдоль траектории, по которой летит персонаж, как в Geometry Dash. В конце ползунка
  нарисована стрелка. Держи её, и персонаж летит к ней, заполняя ползунок.
- Заполнил — переходи к следующему. Кто первым заполнит все, тот победил.
  Соперники летят по той же траектории полупрозрачными персонажами.
- Зажата неправильная стрелка — прогресс быстро тает. Ничего не нажато — медленно сползает.
- Управление: стрелки или WASD.
- **Режимы:** «Классика» — без особых правил; «Зеркало» — правильная стрелка противоположна
  нарисованной; «Вслепую» — видна только текущая стрелка; «Хардкор» — без пауз за ошибку,
  но после трёх ошибок игрок выбывает.
- **Темп** выбирается для любого режима. Обычный: стрелку надо держать. Быстрый: ползунков намного
  больше, и каждый заполняется сразу при нажатии правильной стрелки. Нажал не ту — короткая пауза,
  в это время нажатия не считаются. Одна зажатая клавиша даёт только один ползунок: для двух
  одинаковых стрелок подряд нужно отпустить и нажать снова.
- **Сложность** (лёгкая, нормальная, сложная) меняет число ползунков, скорость заполнения,
  штрафы и поведение бота. У каждого сочетания режима, темпа и сложности своя очередь поиска.
- «Найти матч» ставит в очередь. Матч стартует, когда собралось 2–4 игрока.
  Если ты один дольше 12 секунд, подключится бот.
- «Тренировка с ботом» запускает матч сразу и не идёт в статистику.
- Уровень (число ползунков, стрелки, скорость заполнения) генерируется случайно для каждого матча.
- **«Свой трек»:** браузер находит удары в твоём аудиофайле и строит по ним ритм-уровень.
  Файл на сервер не загружается, рекорды хранятся только в браузере.
- Музыку для меню и для матчей можно выбрать в «Скины → Музыка», в том числе свой аудиофайл.
  Файл хранится только в браузере (IndexedDB), на сервер не загружается, и слышишь его только ты.
- Скины ползунков и эффекты победы и серии побед открываются за матчи, победы и серии побед.
- Играть можно только с аккаунтом (ник + пароль). Каждый матч сохраняется: в меню видны
  статистика по режимам и темпам, лучшая серия побед и 10 последних матчей.

Все настройки баланса находятся в `Game/GameRules.cs`.

## Запуск локально

Нужен .NET 10 SDK.

- **Visual Studio (Windows):** открой `ArrowRush.slnx` и нажми ▶ (профиль `http`), откроется http://localhost:5080.
- **Rider / VS Code / терминал (macOS):** `dotnet run`, затем открой http://localhost:5080.

Локально данные лежат в файле `arrowrush.db` (SQLite) рядом с проектом, он создаётся сам.
Чтобы начать с чистой базы, останови сервер и удали этот файл.

Для проверки онлайна нужны **два разных аккаунта**: один аккаунт не может одновременно
играть в двух вкладках. Удобно открыть вторую вкладку в режиме инкогнито.

## Деплой на Render

1. Залей проект в репозиторий на GitHub.
2. На render.com: **New → Web Service** → выбери репозиторий.
3. Настрой сервис:
   - **Language:** `Docker`;
   - **Root Directory:** `ArrowRush` (`Dockerfile` и проект лежат в этой папке);
   - **Advanced → Health Check Path:** `/health`.
4. **Подключи базу:** создай **New → Postgres** в том же регионе, что и сервис, скопируй с её
   страницы **Internal Database URL** и добавь в сервисе игры в **Environment** переменную
   `DATABASE_URL` с этим адресом. Для внешней базы (Neon, Supabase) подойдёт её адрес
   с `?sslmode=require`.
   Без `DATABASE_URL` игра будет хранить данные в SQLite внутри контейнера, и при каждом деплое
   аккаунты и статистика будут **стираться**.
5. Готово: игра будет доступна на `https://<имя>.onrender.com`.

Таблицы создаются автоматически при первом запуске (`EnsureCreated`).

Порт Render передаёт через переменную `PORT`, приложение подхватывает её в `Program.cs`.

**Ограничения бесплатного тарифа:**

- Сервис засыпает после 15 минут без входящего трафика, первый заход после этого занимает около минуты.
- Бесплатная база Postgres перестаёт работать через 30 дней после создания. Ещё 14 дней её можно
  перевести на платный тариф, потом Render удалит её вместе с аккаунтами и статистикой.

## Как устроено

```
Program.cs              — настройка сервера, SignalR, статика
Game/GameRules.cs       — все константы баланса
Game/Level.cs           — генерация случайного уровня
Game/Match.cs           — логика матча и бот
Game/MatchManager.cs    — очередь поиска, игровой цикл 20 тиков/с
Game/GameHub.cs         — методы, которые вызывает клиент
Data/AppDb.cs           — база: аккаунты, матчи, ключи шифрования cookie
Data/Database.cs        — выбор базы: PostgreSQL (DATABASE_URL) или SQLite
Data/AccountEndpoints.cs — регистрация, вход, выход, профиль, скины
Data/Skins.cs           — список скинов и условия их открытия
wwwroot/                — клиент (index.html, style.css, app.js)
wwwroot/course.js       — сцена матча: траектория, фон, персонаж
wwwroot/fx.js           — фон меню и эффекты на canvas
wwwroot/music.js        — музыка на Web Audio, свои файлы в IndexedDB
wwwroot/rhythm.js       — режим «Свой трек»
```

**Аккаунты.** Сделаны на ASP.NET Core Identity: пароли хранятся только как хеш (PBKDF2),
после 5 неверных паролей вход блокируется на 5 минут. Вход хранится в HttpOnly-cookie
`arrowrush.auth` на 30 дней, она продлевается при каждом заходе. Ключи шифрования cookie
тоже лежат в базе, поэтому перезапуск или деплой никого не разлогинивает.
Ник: 3–16 символов (буквы, в том числе кириллица, цифры, `_ - .`), без учёта регистра.
Пароль: от 6 символов.

HTTP API: `POST /api/account/register`, `POST /api/account/login` (тело `{ userName, password }`),
`POST /api/account/logout`, `GET /api/account/me` (ник, статистика, скины, последние матчи),
`POST /api/account/skin` (тело `{ slot, id }`, надеть открытый скин).
Хаб `/hub` пускает только вошедших, ник берётся из аккаунта.

Сервер авторитарный: клиент отправляет только маску зажатых стрелок (`Input`),
а прогресс считает сервер и 20 раз в секунду рассылает состояние (`state`).
Поэтому напрямую подделать прогресс с клиента нельзя. Но весь уровень приходит клиенту
в `matchStart`, а частота `Input` не ограничена, так что от автонажатий это не защищает.

События сервер → клиент: `queued`, `matchStart`, `state`, `matchEnd`.
Методы клиент → сервер: `FindMatch(mode, fast, difficulty, practice)`, `CancelSearch()`, `Input(mask)`, `LeaveMatch()`.
Значения `mode`: `"classic"`, `"mirror"`, `"blind"`, `"hardcore"`; `difficulty`: `"easy"`, `"normal"`, `"hard"`.

Очередь и идущие матчи хранятся в памяти сервера, поэтому при деплое или перезапуске они обрываются
и не сохраняются. Запускать несколько экземпляров сервиса нельзя.

В быстром темпе сервер засчитывает нажатие сразу, когда приходит `Input`, а не раз в тик.
Клиент применяет те же правила у себя (`predictPress` в `app.js`), чтобы ползунок
заполнялся мгновенно, и сверяется с сервером.

Траекторию сервер не знает: `course.js` строит её из id матча, поэтому у всех игроков она одинаковая.
Секции пути (зигзаг, плавные волны, дуги, прямая) и их палитры меняются через порталы, персонаж остаётся тем же. Сцена качается
по ударам в музыке (`music.energy()`), на дропах вспыхивает (`music.part()`).
Встроенный трек матча идёт разделами: отсчёт — нарастание, на «СТАРТ!» дроп,
дальше затишье, нарастание и второй дроп.

Новые колонки в уже существующей базе добавляет `Database.EnsureDatabase` (`AddColumnIfMissing`),
поэтому старые аккаунты и история сохраняются.

## Что можно добавить дальше

- Таблицу рекордов по всем игрокам (данные уже есть в `MatchParticipants`).
- Смену пароля и восстановление доступа по почте.
- Миграции EF Core вместо `EnsureCreated`, когда схема базы начнёт меняться.
- Приватные комнаты по коду, чтобы играть с друзьями.
- Рейтинг (ELO) и подбор соперников по силе.
