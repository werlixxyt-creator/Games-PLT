# Arrow Rush

Онлайн-игра: зажимай нужную стрелку, заполняй ползунки один за другим быстрее соперников.
Сервер — ASP.NET Core 10 + SignalR (WebSocket), клиент — обычная страница (HTML/CSS/JS).

## Правила

- Под каждым ползунком нарисована стрелка. Держи её, и ползунок заполняется.
- Заполнил — переходи к следующему. Кто первым заполнит все, тот победил.
- Зажата неправильная стрелка — прогресс быстро тает. Ничего не нажато — медленно сползает.
- Управление: стрелки или WASD.
- **Режим «Скорость»**: ползунков 20–30, и каждый заполняется сразу при нажатии правильной стрелки.
  Нажал не ту — пауза 0.5 с, в это время нажатия не считаются. Одна зажатая клавиша даёт
  только один ползунок: для двух одинаковых стрелок подряд нужно отпустить и нажать снова.
  У каждого режима своя очередь поиска и своя статистика.
- «Найти матч» ставит в очередь. Матч стартует, когда собралось 2–4 игрока.
  Если ты один дольше 12 секунд, подключится бот.
- Уровень (число ползунков, стрелки, скорость заполнения) генерируется случайно для каждого матча.
- Играть можно только с аккаунтом (ник + пароль). Каждый матч сохраняется: в меню видны
  статистика (матчи, победы, % побед, заполненные ползунки) и 10 последних матчей.

Все настройки баланса находятся в `Game/GameRules.cs`.

## Запуск локально

Нужен .NET 10 SDK.

- **Visual Studio (Windows):** открой `ArrowRush.slnx` и нажми ▶ (профиль `http`), откроется http://localhost:5080.
- **Rider / VS Code / терминал (macOS):** `dotnet run`, затем открой http://localhost:5080.

Локально данные лежат в файле `arrowrush.db` (SQLite) рядом с проектом, он создаётся сам.
Чтобы начать с чистой базы, останови сервер и удали этот файл.

Для проверки онлайна нужны **два разных аккаунта**: один аккаунт не может одновременно
играть в двух вкладках. Удобно открыть вторую вкладку в режиме инкогнито.

## Деплой на Railway

1. Залей папку в репозиторий на GitHub.
2. На railway.com: **New Project → Deploy from GitHub repo** → выбери репозиторий.
   Railway сам найдёт `Dockerfile` (это указано в `railway.json`).
3. Service → **Settings → Networking → Generate Domain**.
4. **Подключи базу:** в проекте **+ New → Database → PostgreSQL**. Затем в сервисе игры
   **Variables → New Variable**: `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`.
   Без этого игра будет хранить данные в SQLite внутри контейнера, и при каждом деплое
   аккаунты и статистика будут **стираться**.
5. Готово: игра будет доступна на `https://<имя>.up.railway.app`.

Таблицы создаются автоматически при первом запуске (`EnsureCreated`).

Порт Railway передаёт через переменную `PORT`, приложение подхватывает её в `Program.cs`.
Здоровье сервиса проверяется по адресу `/health`.

## Как устроено

```
Program.cs              — настройка сервера, SignalR, статика
Game/GameRules.cs       — все константы баланса
Game/Level.cs           — генерация случайного уровня
Game/Match.cs           — логика матча и бот
Game/MatchManager.cs    — очередь поиска, игровой цикл 20 тиков/с
Game/GameHub.cs         — методы, которые вызывает клиент
Data/AppDb.cs           — база: аккаунты, матчи, ключи шифрования cookie
Data/Database.cs        — выбор базы: PostgreSQL (DATABASE_URL) или SQLite
Data/AccountEndpoints.cs — регистрация, вход, выход, профиль
wwwroot/                — клиент (index.html, style.css, app.js)
```

**Аккаунты.** Сделаны на ASP.NET Core Identity: пароли хранятся только как хеш (PBKDF2),
после 5 неверных паролей вход блокируется на 5 минут. Вход хранится в HttpOnly-cookie
`arrowrush.auth` на 30 дней, она продлевается при каждом заходе. Ключи шифрования cookie
тоже лежат в базе, поэтому перезапуск или деплой никого не разлогинивает.
Ник: 3–16 символов (буквы, в том числе кириллица, цифры, `_ - .`), без учёта регистра.
Пароль: от 6 символов.

HTTP API: `POST /api/account/register`, `POST /api/account/login` (тело `{ userName, password }`),
`POST /api/account/logout`, `GET /api/account/me` (ник, статистика, последние матчи).
Хаб `/hub` пускает только вошедших, ник берётся из аккаунта.

Сервер авторитарный: клиент отправляет только маску зажатых стрелок (`Input`),
а прогресс считает сервер и 20 раз в секунду рассылает состояние (`state`).
Поэтому подделать прогресс с клиента нельзя.

События сервер → клиент: `queued`, `matchStart`, `state`, `matchEnd`.
Методы клиент → сервер: `FindMatch(mode)` (`"classic"` или `"speed"`), `CancelSearch()`, `Input(mask)`, `LeaveMatch()`.

В «Скорости» сервер засчитывает нажатие сразу, когда приходит `Input`, а не раз в тик.
Клиент применяет те же правила у себя (`predictPress` в `app.js`), чтобы ползунок
заполнялся мгновенно, и сверяется с сервером.

Новые колонки в уже существующей базе добавляет `Database.EnsureDatabase` (`AddColumnIfMissing`),
поэтому старые аккаунты и история сохраняются.

## Что можно добавить дальше

- Таблицу рекордов по всем игрокам (данные уже есть в `MatchParticipants`).
- Смену пароля и восстановление доступа по почте.
- Миграции EF Core вместо `EnsureCreated`, когда схема базы начнёт меняться.
- Приватные комнаты по коду, чтобы играть с друзьями.
- Звуки и эффекты при заполнении ползунка.
- Рейтинг (ELO) и подбор соперников по силе.
